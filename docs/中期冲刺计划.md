# 中期检查冲刺计划（3–4 天）

> 目标：在中期检查前交付一个**可运行的基础原型**，现场演示「可追溯 + 可核查」这个核心卖点。
> 时间：≤ 1 周，目标 3–4 天（周末冲刺）。检查具体日期待定，按「越快越好」推进。

## 一、原型要展示什么（MVP 定义）

**一句话**：现场输入一个问题，系统跑出「一段综述 + 每句话对应的原文证据（页码 + 原文 + 置信度）」。

**必须有（核心）**：

- [x] 端到端跑通：问题 → 检索 → 生成 → 拆句 → 每句匹配证据 → 输出对照
- [x] 每句能显示命中的证据：页码 / para_id / 原文片段 / NLI 结果（entailment + 概率）
- [x] 1 篇测试 PDF 跑通（用现成那篇就行）

**中期前砍掉（之后再做）**：

- BM25 混合检索
- 好看的 Gradio 界面（先命令行/纯文本，Gradio 是加分项）
- 评价指标 compute_metrics、人工标注集
- 多篇 PDF

> 原则：中期评审只看「核心创新是否立得住」——即每句话能不能追溯到原文。其余都是锦上添花。
