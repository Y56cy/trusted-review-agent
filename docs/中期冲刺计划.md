## 〇、这次冲刺和上一版的区别（先说重点）

上一版冲刺交付了「单篇 PDF 问答」的最小 Demo。这次要**对齐申请书的核心设想**，把三件事补上：

1. **多篇文献库**：不再只上传一篇，而是把 5 篇 PDF 建成一个文献库，基于整库检索生成综述。
2. **检索/证据可追溯**：每个证据片段都能追到「来自哪篇文献、第几页、第几段」——靠新增的 **`source`（文献名）字段**贯穿全链路。
3. **左右对照展示**：界面改成左「综述」、右「原文证据」对照，点每句话右侧显示证据原文 + 文献名 + 页码。

> 核心卖点不变：综述每一句都能追溯到原文，供人工核查。句级匹配只提供「证据支持 + 人工核查依据」，不声称证明事实正确。

## 一、MVP 定义（中期要演示什么）

**一句话**：现场导入 5 篇相关文献 → 输入一个综述主题 → 系统生成一段综述 → 左边看综述、右边点每句话看到对应的原文证据（文献名 + 页码 + 原文 + 置信度）。

**必须有（核心）**：

- [ ] 多篇 PDF 导入建库（≥3 篇演示，目标 5 篇）
- [ ] 基于整库的混合检索 → 综述生成
- [ ] 每句话能追到证据：**文献名 / 页码 / 段号 / 原文 / NLI 概率**
- [ ] 左右对照界面（左综述、右证据）

**中期前砍掉（之后再做）**：

- 评价指标 `compute_metrics`（公式待定，结题再做）
- PDF 原页坐标高亮（现在做「显示证据原文」即可，跳转 PDF 原页是结题迭代项）

## 二、核心接口变更（三个人都先看这里）

这次改动**只有一个字段**：所有层级新增 `source`（文献名，取文件名，不含扩展名）。

```
parser.parse_pdf(pdf_path)              → [{"text","page","para_id","source"}]
retriever.build_index(paragraphs)        → 不变，段落透传 source
retriever.search(query, top_k)           → [{"text","page","para_id","source","score"}]
match.match_sentence(sentence, cands)    → [{"para_id","page","source","text","nli_label","nli_prob"}]
pipeline.run_review(query, pdf_paths)    → pdf_paths 支持「列表」，返回的 evidences 带 source
```

**段落唯一标识 = (source, para_id)**，para_id 保持「篇内从 1 开始」不再改（多篇靠 source 区分）。

> 单篇场景完全向后兼容：source 就是那一篇的文件名，para_id 仍从 1 开始。
