## 3. 模块接口约定（并行不打架的关键）

**本次唯一变更：所有层级新增 `source`（文献名 = 文件名，不含扩展名）。**

| 模块 | 输入 | 输出（约定格式） | 谁维护 |
| --- | --- | --- | --- |
| parser | PDF 路径 | `[{"text","page","para_id","source"}]` | 队长 |
| retriever | query, top_k（可选 method=hybrid/vector/bm25） | `[{"text","page","para_id","source","score"}]` | 组员 A |
| match | 生成句 + 候选 | `[{"sentence","evidences":[{"para_id","page","source","text","nli_label","nli_prob"}]}]` | 队长 |
| app（界面） | 用户问题 | 读 match 输出做左右对照展示 | 组员 B |

**约定规则**：

- 段落唯一标识 = `(source, para_id)`；`para_id` 保持「篇内从 1 开始」，多篇靠 `source` 区分。
- 检索接口补充（沿用组员 A 既定）：默认 hybrid；`score` 仍为 BGE 余弦相似度，混合模式列表次序即 RRF 排名，不可按 score 重排。原有调用继续可用，仅多返回一个 `source` 字段。
- 组员 A 只改 `retriever.py` 和评测脚本；组员 B 只改 `app.py`；互不碰对方文件。
- 队长改 `parser.py` / `pipeline.py` / `match.py`（D1 加 `source` 时一并完成了 `retriever.py` 的 `source` 透传）；接口变了必须先更新这张表、通知组员再让组员开工。
- 标注格式沿用组员 A 的 `data/retrieval/queries.example.json`，多篇时段落标识加 `source` 字段。

## 4. 协作流程

- **git 分支**：每人一个分支（如 `feat/bm25`、`feat/ui`），队长 review 后合并到 `main`。
- **提交纪律**：不 `git add .`，不提交 `models/`、`venv/`、PDF 原文。
- **进度同步**：对照《中期冲刺计划》的 D1–D10 逐条对齐。
