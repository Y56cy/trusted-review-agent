# 分工文档

> 用途：明确「谁负责什么、模块之间怎么对接、怎么协作同步」。
> 维护人：队长。

## 1. 角色与职责（先定角色，再对号入座）

| 角色 | 负责模块 | 阶段 | 需要技能 | 具体任务 |
| --- | --- | --- | --- | --- |
| **队长（你）** | 架构 + 核心链路 + 集成 | 阶段1、阶段4指标、阶段5联调 | Python、读懂 NLI/向量检索、整合能力 | 搭框架、定接口、写句级匹配、定标注格式、管进度 |
| **组员 A** | 检索与数据 | 阶段2 + 阶段4标注参与 | Python、会跑模型、细心 | BM25 混合检索、检索评测、语料准备 |
| **组员 B** | 展示与评测 | 阶段3 + 阶段4跑分 + 阶段5文档 | Python + Gradio（偏前端）、会写文档 | 界面、溯源展示、导出、评测跑分、写文档 |

**对号入座**：把两位组员填进 A / B。若某人更偏前端，就把 B 给他；更偏数据/模型，就给 A。两个角色工作量相当，可互换。

## 2. 关键路径（重要）

> 你先完成 **阶段1 + 定义好接口**，组员 A/B 才能并行开工（阶段2/3）。
> 所以阶段1是瓶颈，优先做；接口是「分叉点」，定好后三人不互相等。

## 3. 模块接口约定（并行不打架的关键）

这些接口一旦定死，三人就能各改各的文件、不冲突：

| 模块 | 输入 | 输出（约定格式） | 谁维护 |
| --- | --- | --- | --- |
| parser | PDF 路径 | `[{"text","page","para_id"}]` | 队长（已定，别改） |
| retriever | query, top_k | `[{"text","page","para_id","score"}]` | 组员 A |
| match | 生成句 + 候选 | `[{"sentence","evidences":[{"para_id","page","text","nli_label","nli_prob"}]}]` | 队长 |
| app（界面） | 用户问题 | 读 match 的输出做展示 | 组员 B |

**约定规则**：

- 组员 A 只改 `retriever.py`；组员 B 只改 `app.py`；互不碰对方文件。
- 队长改 `match.py` 和接口；接口变了要先通知，再让组员开工。
- 任何人改接口，必须在《分工文档》这张表里同步更新。

## 4. 协作流程

- **git 分支**：每人一个分支（如 `feat/bm25`、`feat/ui`），队长 review 后合并到 `main`。
- **提交纪律**：不 `git add .`，不提交 `models/`、`venv/`、PDF（决策 6）。
- **进度同步**：每周一次，对着《执行方案》的 checkbox 逐条对齐。
