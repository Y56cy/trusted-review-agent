# 执行方案：阶段划分与功能清单

## 0. 项目一句话 + 边界

**目标**：面向高校图书馆的科研综述辅助系统，核心卖点是「本地化 + 可追溯 + 可核查」——综述每一句都能追溯到原文出处，供人工核查。

**已锁定边界（不可越界，来自 README 决策）**：

1. 工程流程整合，不追求底层算法创新。
2. 句级证据匹配只提供「证据支持 + 人工核查依据」，**不声称自动证明结论为真**。
3. 只处理文本型 PDF，不做扫描件 OCR。
4. 模型走 ModelScope 本地路径；`transformers==4.46.3` 等版本锁定，不升级。

### 阶段 1 · 句级证据匹配核心链路（核心创新，最高优先级）

**目标**：把「生成句」自动匹配到「原文证据片段」，支撑溯源与核查。这是全项目唯一创新点，评审重点。

**负责人**：队长

**功能点**：

- [x] 拆句 `split_sentences`（已含连续标点边界修复）
- [x] 检索中文过滤（英文段落剔除，阈值 0.3）
- [x] `match_sentence`：向量粗筛 + NLI 精筛（**entailment 且概率 ≥0.7** 才算命中）
- [x] 串成 pipeline：`generate → split → retrieve → NLI → 输出「句↔证据」映射`

**交付物**：`match.py` 完整实现 + 一个端到端 demo（输入问题，输出逐句带证据标注的综述）

**验收标准**：任取一句生成句，能返回命中证据（para_id / 页码 / 相似度 / NLI 概率）；中文证据判断正确，英文证据已被过滤掉。

### 阶段 2 · 检索层增强

**目标**：让证据召回更准（直接决定阶段 1 匹配质量的上限）。

**负责人**：组员 A

**功能点**：

- [x] 检索评测工具（Precision / Recall / MRR + 逐查询结果）
- [ ] 真实文献评测：5 篇 RAG 主题 PDF + 10–20 条人工标注查询（本次冲刺 D4–D5）

**验收标准**：真实文献上给定 N 个测试 query，输出 P/R/MRR，混合检索相对纯向量检索有提升。

## 3. 依赖关系与里程碑

```
阶段1（核心匹配）
   ├── 是阶段3、阶段4的前置（没有匹配结果，就没有溯源展示和评测）
   └── 是瓶颈，优先完成
阶段2（检索增强）── 可与阶段1并行（BM25 是独立增量）
阶段4（人工标注）── 标注是纯人工活，可与阶段1并行
阶段3（界面）    ── 依赖阶段1的接口，接口定好后即可并行
```

**关键里程碑**：

1. ✅ 阶段 0 完成（已达成）
2. 🎯 阶段 1 完成 = 核心创新落地
3. 🎯 阶段 3 完成 = 有可演示原型
