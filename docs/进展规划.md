# 项目进展规划（中期 → 结题）

> 用途：明确中期检查要达到什么、结题最终交付什么、以及约 50 天怎么走。

## 0. 一句话定位（先对齐）

**核心创新只有一个：句级可追溯 + 可核查。** 综述的每一句都能锚定到原文证据，并能把「可追溯度」量化成一个数。检索、生成、UI、GPU 都只是为这件事服务的手段。

判断标准（贯穿全程）：不管加多少功能，只要 **「每一句都能追到原文、追不到就明说」被演示得「可信 + 直观 + 有数字」**，就算成功。

## 1. 现状诊断（诚实版）

**已经 solid（不用再动）**：

- 全链路跑通：解析 → 检索 → 生成 → 句级校验 → 溯源展示；多篇文献库已就位（5 篇 / 443 段）。
- 检索：BGE + BM25 RRF 混合 + 中文过滤，评测工具齐全（组员 A）。
- 界面：左右对照 + 多篇溯源 + 导出（组员 B），196/197 测试通过。
- 边界清晰：不声称证明、只提供核查依据。

**真正的短板（决定「亮眼」的）**：

1. **没有量化证据**：`compute_metrics` 还是未实现，说不出「可追溯度多少」。
2. **幻觉控制是被动的**：现在是「生成完再标出没证据的句」，不是「主动防幻觉」。
3. **溯源不直观**：右侧是纯文字，不是「原页高亮」。
4. **综述质量低**：3–6 句、无结构。
5. **性能**：7B CPU 生成约 2 分钟。**✅ 已解决——确认有 RTX 5060（8GB 显存），可全量 offload，预计降到 10~20 秒。**
6. **匹配模型弱**：NLI 110M，跨语言不可靠。

> 一句话：**地基是好的，「证明它有价值」的部分缺失。** 不是「漏洞百出」，是「还没把价值讲出来」。

## 4. 技术路线（分模块把关）

### 4.1 检索
- 现状够用，中期不动。
- 结题可选：query expansion（改写查询提召回）+ cross-encoder rerank（精排）。低优先级。

### 4.2 句级匹配（核心创新，重点投入）
- 现状：向量粗筛 + NLI(110M) 精筛 + 阈值 0.7。中文可用。
- 中期：保持，但**把「无证据句」显式统计**（喂给覆盖率脚注）。
- 结题：①用 A 的真实标注数据校准阈值；②有 GPU 后可选升级更强的 NLI / reranker；③明确「跨语言不可靠」边界（英文证据不参与匹配）。

### 4.3 生成 + 幻觉控制（「智能兼备」的落点）
三层幻觉控制（层层递进，结题做完）：

1. **输入可靠**：检索质量（已做）。
2. **生成约束**：prompt 强制「只依据证据、不编造」（已做，可加强）。
3. **校验-重写（核心新增）**：生成 → 逐句 NLI 校验 → **无证据句交给模型改写**（回到证据改写，或显式标「未能溯源」）。

第 3 层就是「生成智能体 + 校验智能体」的闭环。它的保证不是「零幻觉」，而是「**没有未标记的幻觉**」——每一句要么有据、要么被明说。

**两智能体综述生成（已定，智能体叙事的落点）**——「可信核心」与「可读扩写」两层分离，不混在一起：

- **证据生成智能体（阶段 1，已有）**：检索 → 生成**可溯源的关键句** → 逐句 NLI 校验 → 输出「每句有据」的可信核心。
- **综述扩写智能体（阶段 2，新增）**：以阶段 1 的关键句为**输入**，按综述思维（引言 / 过渡 / 主体 / 总结）扩写成完整综述。两条硬约束：①关键句保留溯源锚点，不从零重写；②新增的结构句明确标为「综述性扩写（非直接引用）」，不与有证据句混淆。

UX 流程：用户先得到可溯源的关键句 → 点「生成综述」→ 智能体扩写成完整综述。扩写 prompt / 参数后续可单独调试。

### 4.4 效果评价
- **证据覆盖率**（中期就做，免费）：有证据句 / 总句数。
- **检索 P/R/MRR**（A 的 D5，中期交付）。
- **可核查准确率**（结题）：人工标注「这句子是否真有据」，算匹配准确率——这是「可核查」的硬指标。

### 4.5 性能 / GPU（✅ 已确认）
- **硬件已确认**：NVIDIA GeForce RTX 5060，8GB 显存（8151 MiB），CUDA 13.1。
- 7B Q4_K_M 权重约 4.7GB，**可全量 offload**，留 3GB 跑上下文。
- **落地步骤**：
  1. 下载 CUDA 版 llama.cpp（Releases 里 `bin-win-cuda-cu13.1-x64`）。
  2. 启动 `-ngl 99`（全层 offload），日志应显示 `offloaded 28/28 layers to GPU`。
  3. 若显存不足，降 `-ngl` 或加 `-c 2048` 缩小上下文。
- 若后续要上更大模型（14B/32B）或超长上下文，再考虑租服务器 / 老师台式机（现在不需要）。

### 4.6 前端
- 中期：现状 + 实时生成，够用。
- 结题：全屏布局 + 结构化证据卡片 + **PDF 原页高亮（PyMuPDF：`page.search_for(证据文本)` 拿坐标 → `add_highlight_annot` 高亮 → 渲染成图展示）** + 综述阅读视图。
- **会议结论（11-14）**：①开发者功能（结果导入 / 语料核对）从主界面隐藏，语料核对改为「生成时自动校验 + 证据旁显示 ✓」；②下载拆成「下载综述」和「证据溯源报告」两个入口；③综述字号 ≥16px + 复制键；④所有 UI 工作遵循 `docs/用户体验规范.md`。

### 4.7 文献规模与智能检索
- **规模**：当前架构（内存向量 + 逐次建索引）扛得住几百~几千篇文献；唯一要补的是「索引持久化」（建一次存磁盘复用）。中期 5 篇不用管。
- **智能检索替代手动上传**：技术上容易（pipeline 输入就是 PDF 路径列表，加一个「主题 → 检索 → 下载」模块即可）；「图书馆 / 知网 API 拿全文」难在**权限 / 版权**，不在技术。
- **现实路径**：结题用 **arXiv 开放接口打样**（免费、有全文 PDF、API 干净）演示「主题自动检索」；图书馆 API 预留接入位、待馆方授权（报告里如实写）。

## 6. 风险与对策
