  给组员 B 的前端修改清单

  ▎ 目标：把界面从「开发者工具感」改成「给最终用户用的清晰美观综述工具」。
  ▎ 核心原则：主流程（上传 → 生成 → 左右对照 → 下载综述）突出，开发者 /
  ▎ 核查类功能默认隐藏。

  1. 布局：全屏 + 协调（P0）

  - [ ] 主界面满宽铺满视口，去掉居中窄列和多余留白。
  - [ ] 左右对照区用满宽度：左综述 / 右证据，比例协调（约 4:6）。
  - [ ] 模块切换用 gr.Accordion（折叠面板）或
  gr.Tabs，避免点击"添加文献""导出报告"时页面大幅跳变（这是"僵硬"的根因）。

  2. 隐藏开发者痕迹（P0）

  - [ ] "结果导入"、"语料核对"从主界面移除（不出现在用户第一眼）。
  - [ ] 保留"演示样例"入口（用户可见，明确标注为演示）。

  3. 语料核对：换形态、不删除（P1）

  - [ ] 把「语料一致性校验」自动做进生成流程：生成结果里每条证据旁自动显示校验
  状态（有冻结语料时"✓ 已通过语料一致性校验"，无则"未校验"）。
  - [ ] 不要求用户手动选 corpus.json / result.json 两个文件。

  4. 文字样式（P0）

  - [ ] "原始综述全文"字号调大（≥16px），行距舒适。
  - [ ] 综述全文加复制按钮（gr.Textbox(show_copy_button=True)）。

  5. 下载拆分（P1）

  - [ ] 下载区分两个入口：
    - 「下载综述」：干净排版的综述（Markdown，后续加 docx / pdf）。
    - 「证据溯源报告」：现有 MD/CSV/JSON/HTML 四种（改名，收进高级区）。

  6. 上传说明（P0）

  - [ ] "1–10 篇"上限在界面说明清楚原因（每篇 ≤50MB、总计 ≤200MB
  是为了防止拖垮本地生成），或按需调整上限。
