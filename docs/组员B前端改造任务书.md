## 2. 任务清单

### A. 布局与交互（P0）

- 满宽铺满视口，去掉居中窄列；左右对照约 4:6，主内容占主要面积。
- 模块切换用 `gr.Accordion` / `gr.Tabs`，避免点「添加文献」「导出」时页面大幅跳变。
- 响应式：窗口变窄时布局合理降级，无横向滚动。

### B. 隐藏开发者痕迹（P0）

- 「结果导入」「语料核对」移出主界面第一眼，收进「高级」折叠区。
- 主流程一屏可见：上传文献 → 研究问题 → 生成 → 左右对照 → 下载。
- 保留「演示样例」入口（用户可见，明确标注为演示）。

### C. 文字样式（P0）

- 综述正文字号 ≥16px，行距 1.6~1.8。
- 综述全文加复制按钮：`gr.Textbox(show_copy_button=True)`。
- 关键信息（文献名/页码/段号/置信度）用色块/徽章区分，不混在正文里。

### D. 上传说明（P0）

- 界面说明「1–10 篇」上限原因：每篇 ≤50MB、总计 ≤200MB，是防止一次传太多拖垮本地生成（保留上限，说清即可）。

### E. 下载拆分 + docx（P1）

- 下载拆成两个入口：
  - **「下载综述」**：干净排版的综述全文，本轮产出 **docx**（用 `python-docx`，纯 UI 从 result 生成，无后端耦合），Markdown 保留。
  - **「证据溯源报告」**：现有 MD/CSV/JSON/HTML 四种，改名收进「高级」区。
- `requirements-ui.txt` 加一行 `python-docx`（选一个与现有环境兼容的版本，锁进 `requirements-ui.lock.txt`）。

### F. 语料一致性校验换形态（P1，本轮重点）

把现有「语料核对」页签从「事后手动选两个文件核对」改成「生成时自动校验 + 证据旁显示 ✓」：

- **只改 app.py**：现有 `validate_frozen_corpus` + `check_corpus_evidence` 已经在本文件，重构成**内存版**——接收「生成结果 + 冻结语料 index」，返回每条证据的 `corpus_verified`（true/false）。
- **冻结语料输入**：在「高级」折叠区加一个可选的「冻结语料」上传（单个 `corpus.json`，用 `validate_frozen_corpus` 校验），配置一次后每次生成自动校验。
- **显示**：每条证据旁自动显示 `✓ 已通过语料一致性校验` / `⚠ 与冻结语料不一致` / `未校验`（未加载语料时）。
- **导出**：`corpus_verified` 状态随 Markdown/CSV/HTML/JSON 导出保留。
- 注意：`validate_result` 目前会重建证据字典、只保留固定字段，需同步放行 `corpus_verified`，否则该字段会被丢掉。
