## 0. 现状与目标（一句话）

**现状**：全链路（解析→检索→生成→句级校验→溯源展示）已跑通，GPU 秒级生成已验证，多篇文献库就位。P0 生成-校验-重写闭环、P1 综述扩写智能体、引用标注（`[N]` 上标 + 参考文献表）、线2 前端改造均已完成；20 条查询复核包已就绪，待双人汇总定稿。

**目标**（进展规划 §3 最终形态）：一条龙演示「导入文献 → 生成结构化综述 → 逐句高亮原页证据 → 无证据句被主动改写或标出 → 一键导出报告 + 可追溯度评分」。

**创新点始终只有一个**：句级可追溯 + 可核查。下面所有任务都为它服务。

## 2. 线1 · 核心功能（队长）

### 2.1 生成-校验-重写闭环（P0，最高优先）✅

**解决什么**：幻觉控制从「被动标出」升级为「主动防幻觉」——这是「智能体」故事的核心落点。

**现状**：pipeline 已能「生成 → 拆句 → NLI 校验 → 标出无证据句」，但无证据句只是被标出，没有下一步。

**要做**：无证据句 → 交给模型改写（回到证据改写）→ 改写后再走一遍 NLI 校验 → 改不动就显式标「未能溯源」。

**验收标准**：
- [x] 跑通「生成 → 校验 → 无证据句改写 → 再校验」闭环，界面能体现改写前后对比。
- [x] 最终结果里每一句满足：**要么有据、要么被明说「未能溯源」**，不存在「未标记的幻觉」。
- [x] 改写不引入新幻觉（改写后仍走 NLI 校验，不通过则标记而非硬编）。

### 2.2 PDF 原页高亮溯源（P0）⬜

**解决什么**：溯源从「右侧文字」升级为「原页高亮」，这是结题视觉核弹。

**现状**：右侧显示证据原文（文字 + 文献名/页码/段号），无原页坐标。

**要做**：PyMuPDF `page.search_for(证据文本)` 拿坐标 → `add_highlight_annot` 高亮 → 渲染成图展示。段落超长或跨页时按证据片段定位。

**验收标准**：
- [ ] 点句子 → 右侧显示对应 PDF 原页图片，证据片段被高亮。
- [ ] `search_for` 失败时**退化为段落卡片高亮**（不阻塞，见进展规划 §6 风险表）。
- [ ] 与线2 前端衔接（先给 B 约定返回坐标/图片的接口）。

### 2.3 两智能体综述扩写（P1）✅

**解决什么**：综述从「3–6 句无结构」升级为「结构化完整综述」，是「智能体」叙事的下半场。

**要做**（进展规划 §4.3 已定，两阶段）：
1. **证据生成智能体**（已有）：检索 → 生成可溯源关键句 → 逐句 NLI 校验。
2. **综述扩写智能体**（新增）：以关键句为输入，按综述思维（引言/过渡/主体/总结）扩写。两条硬约束：①关键句保留溯源锚点，不从零重写；②新增结构句明确标「综述性扩写（非直接引用）」。

**验收标准**：
- [x] UX 流程：先得可溯源关键句 → 点「生成综述」→ 扩写成完整综述。
- [x] 关键句在扩写后仍能点开看证据；结构句与有证据句视觉可区分。

### 2.4 智能文献检索 arXiv 打样（P1）⬜

**解决什么**：替代手动上传、补「图书馆场景落地感」（结题报告如实写：图书馆 API 待授权，用 arXiv 打样）。

**验收标准**：
- [ ] 输入主题 → arXiv 检索 → 下载 PDF → 进 pipeline，一条龙跑通。
- [ ] 图书馆/知网 API 预留接入位，报告如实写权限限制。

## 7. 风险与对策（沿用进展规划 §6）

| 风险 | 对策 |
|---|---|
| 校验-重写闭环引入新幻觉 | 改写后仍走 NLI 校验，改不动就显式标「未能溯源」 |
| PDF 高亮定位不准（文字层乱） | `search_for` 失败退化为段落卡片高亮，不阻塞 |
| 超长段检索漏召回（>512 token） | 已记录为可解释局限，评测报告如实说明，不归咎标注 |
| 时间不够 | 按 P0 → P1 砍，P1 的 arXiv 检索 / 前端美化可整块降级 |

## 8. 每阶段「完成」的定义（评估口径）

一条工作线「完成」= 验收标准全勾 + 相关测试不回归 + 文档 checkbox 同步更新。**不允许「代码做完但 checkbox 没勾」或「勾了但没验收」**。

进度同步：对照本表逐条对齐，周会收尾更新。D4/D5 评测的真实结果出来后，补进线3 并回填《执行方案》阶段 2/4 的 checkbox。
