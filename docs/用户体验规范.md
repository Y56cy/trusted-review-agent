# 用户体验规范

> 用途：所有涉及界面（`src/app.py` / 前端）的工作，都要遵守本规范。
> 写任务说明时把本规范一并喂给 AI，产出才会符合预期。
> 维护人：队长。

## 0. 定位原则

界面是给**最终用户**（图书馆场景的师生）看的，不是给开发者看的。
判断标准：一个不懂技术的人，能不能 **30 秒看懂怎么用、且觉得清爽可信**。

## 1. 布局

- 满宽铺满视口，不做居中窄列。
- 左右 / 上下结构比例协调，主内容占主要面积。
- 响应式：窗口变窄时布局合理降级，不出现横向滚动。

## 2. 主流程突出

- 主流程 = 上传文献 → 输入问题 → 生成综述 → 逐句看证据 → 下载。
- 主流程组件放第一屏，一眼可见。
- 非主流程（导入历史结果、语料核对、环境自检等）**默认隐藏**，或收进「高级」折叠区。

## 3. 交互

- 切换 / 展开用折叠面板（Accordion）或标签页（Tabs），不做突兀的整页跳变。
- 点击有反馈（loading 提示、禁用态），避免「点了没反应」。

## 4. 文字排版

- 综述正文字号 ≥ 16px，行距 1.6~1.8。
- 关键信息（文献名、页码、段号、置信度）用色块 / 徽章区分，不混在正文里。
- 长文本提供复制按钮（`gr.Textbox(show_copy_button=True)`）。

## 5. 下载

- 明确区分两个入口：
  - **「下载综述」**：用户要的成果，干净排版，优先 Markdown，后续加 docx / pdf。
  - **「证据溯源报告」**：核查用，收进高级区。

## 6. 命名与文案

- 用用户语言，不用开发者术语。
- 诚实文案：不声称「证明正确」，用「证据支持」「可人工核查」等表述（与项目边界一致）。

## 7. 检查清单（做完 UI 逐条自检）

- [ ] 满宽、无横向滚动
- [ ] 主流程一屏可见，高级功能折叠
- [ ] 综述字号 ≥ 16px，有复制按钮
- [ ] 下载分「综述」和「证据报告」两类
- [ ] 无开发者术语外泄到用户界面
- [ ] 证据卡片有文献名 / 页码 / 段号 / 置信度，样式清晰
