## 一、已取得成果

> **概述**：本项目已完成「文献解析→证据检索→综述生成→句级校验→溯源展示」全链路原型，核心创新「句级可追溯」落地。系统支持多篇文献建库（5 篇 RAG 主题论文、443 段），采用 BGE+BM25 混合检索与本地 Qwen2.5-7B 生成综述，逐句 NLI 校验锚定原文证据。已实现生成-校验-重写闭环（主动防幻觉）与两智能体综述扩写（可溯源关键句→结构化综述）。前端左右对照逐句溯源、四格式导出，GPU 加速后生成降至 10~20 秒。检索评测工具与 20 条真实查询标注就绪，205 项单元测试通过。

本项目已完成从「文献解析」到「溯源展示」的全链路原型，核心创新「句级可追溯」已落地并进入结题阶段的功能推进。

### 1. 全链路原型（六模块）

`文献解析 → 证据检索 → 综述生成 → 句级校验 → 溯源展示 → 效果评价` 已一条命令跑通。

- **文献解析**：PDF → 段落（带页码/段号/文献名），面向文本型 PDF，多篇合并建库。
- **证据检索**：BGE 向量检索 + BM25 关键词检索的 RRF 混合检索，配中文占比过滤（阈值 0.3）。
- **综述生成**：本地 llama.cpp + Qwen2.5-7B 大模型，全流程本地化、不依赖云端。
- **句级校验**：拆句 + 向量粗筛 + NLI 精筛（Erlangshen-110M，entailment 且概率 ≥0.7）。
- **溯源展示**：Gradio 界面，左右对照，点句看原文证据（文献名/页码/段号/置信度）。

### 2. 核心创新：句级可追溯 + 可核查

- 综述**每一句**都能锚定到原文证据片段，或**显式标注「未能溯源」**，不声称自动证明结论为真。
- **生成-校验-重写闭环**（主动防幻觉）：生成 → 逐句 NLI 校验 → 无证据句交给模型改写 → 改写后再校验 → 改不动则显式标「未能溯源」，保证「没有未标记的幻觉」。
- **两智能体综述生成**：证据生成智能体（可溯源关键句）+ 综述扩写智能体（按引言/过渡/主体/总结扩写成完整综述，关键句保留溯源锚点、结构句标记「综述性扩写」）。

### 3. 多篇文献库与检索评测

- 冻结语料：5 篇 RAG 主题真实论文，443 段（中文过滤后 324 段），逐文献 SHA-256 绑定。
- 检索评测工具：Precision / Recall / MRR 三指标 + 逐查询排名与案例分类，支持 vector / bm25 / hybrid 三模式。
- 真实标注：20 条查询（6 开发集 / 14 保留集）+ 候选证据初稿 + 双人复核包（含原 PDF、全库原文、可填写复核网页）。

### 4. 性能与工程

- GPU 加速：RTX 5060（8GB）+ CUDA 版 llama.cpp，生成从约 2 分钟降至 10~20 秒。
- 自动化测试：205 项单元测试通过；Ruff 静态检查通过。
- 团队协作：git 分支 + 模块接口约定，成员 A（检索/评测）、成员 B（界面）并行推进。

## 四、项目存在问题及解决方案

1. **综合/总结类句子难以溯源，未能溯源率偏高**（实测部分查询达 50%）。综述中「总结/综合」性质的句子（往往是主题句）天然难以锚定到单条证据，导致可信核心偏稀疏、部分主题句被丢弃。解决方案：调优检索 `top_k` 与 NLI 阈值，改进生成 prompt 引导生成「可直接溯源的陈述句」，并把综合句交给扩写智能体的引言/过渡/总结承担。

2. **NLI 模型跨语言不可靠**（英文证据 + 中文生成句判断不准），影响英文段落证据的匹配。解决方案：检索侧已用中文占比过滤（阈值 0.3）剔除英文段，并明确边界「英文证据不参与匹配」。

3. **长段落超 BGE 512 token 截断**，段末证据可能漏召回、Recall 偏低。解决方案：评测报告中如实说明该局限；结题可做长段切分或索引持久化。

4. **PDF 解析存在语料污染与公式乱码**（丁咚论文尾页混排、曹启航论文公式乱码），个别段落质量受影响。解决方案：已记录为数据质量边界——污染段保留作干扰、公式乱码不纳入查询，报告不声称清洗完成。

5. **性能瓶颈：NLI 逐句 CPU 推理 + 每次 run 重新加载模型**，全链路仍有数秒延迟。解决方案：结题优化为模型常驻（加载一次复用）与 NLI 批量推理。

6. **评价指标 `compute_metrics` 未实现**，尚无法输出「可追溯度」量化数值。解决方案：定公式后实现证据覆盖率（有证据句/总句数）与可核查准确率（人工标注「句子是否真有据」）。
