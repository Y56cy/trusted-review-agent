# 成员 B 多篇联调与录屏清单

适用于上游 D1 `1d37b0f` 的多篇接口。本文是待执行清单，不是已完成的真实实验记录；正式效果跑分仍等指标与人工标注。不要用手工演示替代真实生成截图。

## 联调前准备（队长 / 成员 A 提供）

- [ ] 确认主题及 3–5 篇授权使用的文本型 PDF；文件名不含扩展名后互不重复。
- [ ] 记录文献清单：文件名、题名、公开来源或授权、页数。PDF 原文不要提交到 Git。
- [ ] 准备 Python 3.12 核心环境、锁定版本的 BGE/NLI 依赖、本地模型权重和 llama-server。
- [ ] 在当前机器确认 NLI 路径有效，不直接沿用其他电脑的绝对路径。
- [ ] 用启动 UI 时相同的 `--backend-python` 跑 `--check --json`；保存实际自检结果。基础检查通过不等于真实链路通过。

## 真实联调（成员 B 记录结果）

1. 先上传一篇真实 PDF 完成生成，记录实际主题、运行时间、文献名与参数。
2. 上传至少三篇，目标五篇，输入跨文献综述问题，确认生成任务使用同一文献库。
3. 左侧逐句点击，右侧只显示该句的文献名、页码、段号、原文与 NLI 概率。至少人工查回两篇不同 PDF 的对应页；没有命中某篇文献本身不等于程序错误，不伪造命中。
4. 遇到无证据句时确认右侧显示人工核查提示，没有上句残留。点击“查看全部证据”，再测试浏览器后退、前进和重复选择。
5. 下载 Markdown / CSV / JSON / HTML，逐条核对文献名及原文顺序；HTML 离线打开，JSON 回导显示“来源未核验”。
6. 清空后再次生成；坏 JSON、无 PDF、空问题、重复 stem PDF 应明确失败且不残留旧下载。超时是停止任务，不是生成成功。
7. 在宽屏和窄屏检查左右/上下布局及键盘焦点。录屏前关闭含个人路径或不相关内容的窗口。

记录模板：日期、代码 commit、核心 Python/模型配置、论文清单、问题与参数、通过项、失败项及错误原文、报告与截图所在位置。未执行项写“未执行”，不要填“通过”。

## 录屏顺序（真实联调通过后）

1. 介绍边界：“本系统整合本地生成、检索和句级证据匹配，帮助人工核查，不自动证明事实正确。”
2. 展示已准备的 3–5 篇文献，输入主题并生成；若剪辑等待过程，标注实际耗时，不把演示样例当现场结果。
3. 点选两个来自不同文献的证据片段，展示文献名、页码、原文；切到无证据句并解释需要人工核查。
4. 下载 HTML/JSON，演示可离线核查和回导。
5. 说明当前未覆盖：扫描件 OCR、PDF 坐标高亮、正式效果评价。

如果模型环境尚未就绪，只可录制明确标记“手工演示数据”的界面预览，用于交互说明，不能作为真实多篇检索/生成的验收证据。
